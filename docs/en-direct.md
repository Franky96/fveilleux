# Soirées « En direct »

Onglet « En direct » de la section Intentions de vote : une page par soirée électorale, avec les résultats lus en direct.
Pour le gabarit et la génération des pages, voir aussi `docs/intentions-de-vote.md`.

## Comment c'est construit

- **Soirées en cours** (`DIRECTS` de `votes-quebec/outils/pages.py`) : un même cadre, le bloc `gen` de `pages.src.html`, avec les textes `{{H2}}`, `{{SUR}}`, `{{CHOIX}}`, `{{CARTE}}` et `{{CLASSEMENT}}`.
  - Chaque page charge son module : `en-direct/direct.js` (États-Unis) ou `en-direct/<endroit>/direct.js`.
  - Le module remplit les zooms (`lvZoom`), le choix (`edChoix`), les blocs du bas (`edBlocs`) et la source (`edSource`).
- **Sous-menu** (`sous-direct` du gabarit) : les soirées dans l'ordre des dates. `PRETES` de pages.py liste les soirées prêtes ; les autres ne sont ni générées ni montrées.
- **Anciennes soirées** : chacune garde son propre bloc dans le gabarit (`cb2026`, `ab2026`) et son module dans `en-direct/<x>-2026/`. Elles sont listées par le bouton « Anciennes élections » de l'Accueil (`ac-anciennes`, gabarit).
- **Chaque soirée a trois sources de résultats, essayées dans l'ordre** :
  1. le relais PHP du site, `api/<x>.php`, avec un cache de 30 à 45 s ;
  2. la source officielle lue directement, seulement si elle permet la lecture depuis un autre site (CORS ; c'est le cas de CNN) ;
  3. la copie de secours du pipeline, `en-direct/<endroit>/resultats.json`, écrite par `outils/<code>.py` et le workflow `<code>-election.yml`.
- **Démo** (admin) : chaque page a un mode `?demo=<année>` qui rejoue l'élection précédente dans le même format, pour tester la lecture des résultats.

## Archiver une soirée terminée

Exemple suivi pour la Colombie-Britannique le 26 octobre 2026 :
1. Déplacer le module et les données dans `en-direct/<x>-2026/` avec `git mv`, puis corriger les chemins dans le module, le script du pipeline, le workflow et le relais.
2. Dans le gabarit, donner à la soirée son propre bloc (`<!-- DEBUT:<vue> -->`), ou garder le cadre `gen`.
3. Dans pages.py, l'ajouter à `FICHIER`, `TITRE`, `SCRIPTS` et `BLOCS`.
4. L'ajouter à la liste « Anciennes élections » du gabarit et la retirer du sous-menu.
5. Laisser tourner son workflow jusqu'aux résultats officiels, puis le laisser expirer (il ne fait rien hors de sa fenêtre).

Pour les soirées de novembre, qui ont déjà chacune leur page et leur dossier, l'archivage se résume à les retirer du sous-menu et à les ajouter à la liste « Anciennes élections ».

## Vérifications le soir de chaque vote

Avant l'heure :
- Ouvrir la page, puis la démo (`?demo=…`) : rien de cassé.
- Lancer le workflow de la soirée à la main (outil GitHub `actions_run_trigger`, avec `--force` par défaut), puis lire son journal : la source répond-elle depuis GitHub ?

À la fermeture des bureaux :
- Les premiers chiffres s'affichent-ils ? La ligne « Vérifiées … » sous l'état dit d'où ils viennent : relais, lecture directe ou copie de secours.
- Si le relais du site ne lit rien, comparer avec le site officiel (lien dans la bannière), puis corriger la lecture dans le module ou l'adresse dans le relais et dans le script du pipeline.
